# Архитектура — этап 4

## Компоновка

`main.cpp` создаёт DockSettings, WindowTracker, ApplicationModel, ApplicationCatalogue и DockPlatform. QML получает типизированные обязательные зависимости через `setInitialProperties`; загрузка остаётся `loadFromModule("MacGlassDock", "Main")`. Пустой корень и ошибочный модуль дают ненулевой exit status.

`Main.qml` владеет нижним Dock и отдельными окнами каталога, настроек, контекстного меню и ошибки запуска. Собственные панели используют GlassPanelWindow. Общий материал не зависит от каталога/модели окон и пригоден для повторного использования.

## Glass Engine

`VolumetricGlassSurface.qml` — единственная реализация стеклянной поверхности. GlassSurface сохранён как совместимый адаптер DockPlatform. Материал принимает radius, density, положение указателя и настройки. Корневые поверхности получают фактическую доступность blur от DockPlatform, вложенные поверхности находятся внутри общей области размытия своего окна.

`glass.frag` вычисляет SDF скруглённого прямоугольника. Профиль толщины формирует нормаль кромки и Fresnel-like коэффициент; тонкий направленный контур и внутренняя тень заменяют старое яркое двойное кольцо. Для маленьких кнопок opticScale уменьшает толщину оптической фаски. Художественные отражения зависят от курсора и нормали; тело почти прозрачно, тень аналитическая, микрозернистости и time uniform нет. Цвет premultiplied, границы сглаживаются производными SDF. Desktop texture отсутствует, поэтому физическое преломление не заявляется.

Каждый материал использует один fragment pass без отдельного framebuffer blur. KWin размывает фон по регионам. Вложенные элементы дают дополнительные небольшие draw calls, но не создают полноэкранные текстурные копии. Soft Glass и software backend используют многозонный QML-градиент с внутренней/внешней кромкой. Вне GPU точное совпадение материала не гарантируется.

`adaptive-icon.frag` — отдельный display-only проход: superellipse-like подложка и выборка полной иконки в квадрате с полями. Логотип не обрезается по форме подложки. Unified Glass использует тот же VolumetricGlassSurface. Image provider читает QIcon из XDG themes, принимает абсолютный путь иконки из desktop entry и тонирует явно symbolic-иконки на копии изображения. Original оставляет исходное отображение. Фиксированное разрешение текстур с DPR предотвращает повторную растеризацию на каждом кадре zoom.

## Платформа и ввод

DockPlatform хранит отдельные регионы для Dock и каждой панели. LayerShellQt размещает Dock снизу на Overlay, с exclusive zone -1 и без keyboard focus. Это позволяет показать его поверх полноэкранного приложения у физического края экрана. Панели используют Overlay и KeyboardInteractivityOnDemand; hover-список окон использует KeyboardInteractivityNone. Они не требуют эксклюзивного перехвата клавиатуры и не накрывают рабочий стол прозрачным input overlay.

Маска ввода Dock — скруглённая поверхность плюс реальные ячейки всех иконок, включая крайние кнопки каталога и настроек. Область blur не включает тени/верхний пустой запас. У панелей shape/input/blur соответствует внутреннему скруглённому прямоугольнику. Все координаты логические, DPR повторно к регионам не применяется. В software offscreen native mask не используется.

Автоскрытие сначала сдвигает/гасит содержимое, затем уменьшает native window до полосы 3 px. Пока полоса скрыта, blur отключён. Hover возвращает полную геометрию и содержимое. При открытых панелях скрытие приостанавливается, preview отключает его. Полоса находится у физического нижнего края, независимо от exclusive zone панели Plasma.

Выбор экрана хранится как Qt screen name; при его отсутствии выбирается primary. Для screenAdded/screenRemoved предусмотрена повторная оценка выбора. Перемещение layer-shell между реальными выходами и hotplug требуют физического multi-monitor теста.

## Данные приложений

ApplicationCatalogue перечисляет KService::allServices, исключает NoDisplay и неподходящее окружение, сортирует QCollator. Поиск учитывает локализованное имя, generic name, keywords и desktop ID. Категории получаются из Freedesktop Categories. KSycoca::databaseChanged обновляет список.

ApplicationModel объединяет закрепления и подтверждённые протоколом работающие приложения. У каждого приложения один desktop ID. Состав обновляется через insert/remove/move без modelReset: существующие делегаты и пружины сохраняются. Running-only группы сортируются по desktop ID, события окон объединяются за один оборот event loop без дополнительной задержки.

KIO::ApplicationLauncherJob запускает desktop entry, обрабатывает аргументы/активацию/ошибки. Job связывается с desktop ID, а не с изменяемым номером строки. Перестановка/удаление закрепления не делает callback адресованным другому приложению. Launching и running — разные роли. Ошибки доступны в модели и собственной стеклянной панели.

## Окна KWin

WindowTracker — отключаемый адаптер KWayland; сборка без библиотеки сохраняет Dock/launcher. Он слушает org_kde_plasma_window_management, группирует окна по app ID/StartupWMClass и учитывает active, minimized и capabilities. Операции используют локальный проверенный token, не shell, не PID guessing и не X11-инструменты.

По умолчанию адаптер не подключается. После явного включения он показывает незакреплённые работающие приложения. Нажатие на активное приложение сворачивает его; на неактивное — активирует или восстанавливает. Выбор конкретного окна доступен в контекстном меню и панели после задержки наведения. Закрытие подтверждается фактическим unmapped, не окончанием анимации.

По запросу пользователя в его текущем профиле адаптер включён. `WindowAnimations` отдельно управляет краткими анимациями нормальных окон в нашем compositor effect; Reduced Motion и отключение интеграции отменяют их.

## Обновление композиторной оптики (21 октября 2026)

`DockPlatform` отправляет изменившуюся геометрию через одноразовый 0-ms coalescing timer. Повторные события не отодвигают отправку. Линзы делегатов ограничиваются clipping ancestors, включая GridView.

Для каждой собственной поверхности KWin создаётся `BackgroundEffectItem`. Он объявляет зависимость от фоновых пикселей в scene damage tracking; простого `setTranslucent()` для KWin 6.8 недостаточно. Фон сохраняется в физическом разрешении текущего viewport; FBO раздельны для каждого RenderView и удаляются при удалении окна/выхода. Постоянного repaint timer нет.

Класс эффекта наследует `OffscreenEffect`: нормальное окно временно направляется в текстуру для деформации, opacity и blur. `TimeLine` движется по кадрам композитора; после завершения снимаются redirect, grab role, visible/deleted refs. Фон, панели, всплывающие, полноэкранные окна и экран блокировки исключаются. Для сопоставленной иконки разрешён переход grab role к нашему эффекту; для остальных окон чужое владение сохраняется. Глобальные настройки других эффектов не отключаются.

Production-библиотеки устанавливаются в отдельные каталоги версий; существующий загруженный `.so` никогда не перезаписывается. Это также обходит кеш фабрик Qt при session-only обновлении. См. REFRACTION.md.

## Временная замена панели и оформление окон

`DesktopIntegration` запускает ограниченный набор действий `desktop-session.py` через QProcess с отдельными аргументами. Рабочие пути заданы при сборке. `status` только читает собственное состояние. `activate` сначала проверяет работающий Dock, затем сохраняет полные копии пользовательских конфигураций и JSON с id, расположением, высотой и составом панелей. Существующие нижние task-manager панели перемещаются влево через Plasma scripting API, виджеты не удаляются. Повторная активация переводит ранее перенесённую наверх панель влево, не подменяя исходный снимок. `restore` восстанавливает конкретные свойства по id и проверяет состав виджетов. Файлы Plasma целиком не переписываются поверх живого процесса.

Без явно включённого автозапуска действует временный режим: `org.macglass.Recovery.desktop` при следующем входе восстанавливает панель и отключает себя (`Hidden=true`). По запросу пользователя добавлен постоянный режим: `enable-autostart` создаёт пользовательский `org.macglass.Dock.desktop`, сохраняет абсолютный путь проекта и отключает Recovery. Независимая копия helper в XDG_STATE_HOME/mac-glass-dock/recover.py выполняет `login`: блокировка flock, ожидание D-Bus KWin/Plasma, проверка уже готового Dock, запуск scripts/session.sh (модуль эффекта, затем приложение), проверка готовности и только затем восстановление ранее выбранного левого расположения панели. Исходный снимок не подменяется текущим. Отложенный старый restore-login проверяет флаг autostart и ничего не меняет в постоянном режиме. При неудачном запуске завершается только созданный helper процесс и выполняется откат панели; пропавший checkout не лишает пользователя программы восстановления. disable-autostart возвращает временный режим, полный restore также отключает автозапуск. Для оформления сохраняются только изменяемые ключи группы org.kde.kdecoration2; остальные настройки KWin не затрагиваются. Сборка/установка сами по себе автозапуск не включают.

Тема `org.macglass.decoration` устанавливается в пользовательский каталог KWin/Decoration и использует Aurorae/QML. Серверный titlebar содержит собственные круглые кнопки с вызовами requestClose, requestMinimize и requestToggleMaximization. Верхние углы округлены; maximized geometry остаётся прямоугольной. CSD приложений тема не заменяет.

## Нижний край, пересечения и источники анимации

LayerShellQt использует `exclusiveZone=-1`: размещение относится к физическому выходу. Видимая поверхность находится примерно в 12 логических px от низа, скрытая полоса — непосредственно у края. KWin слушает Cursor::posChanged и сообщает об указателе в коридоре между Dock и физическим низом. События ввода не перехватываются.

Dock публикует прямоугольники иконок и поверхности относительно центра native window по X и его низа по Y. Это сохраняет привязку при уменьшении скрытого окна до 3 px. Сопоставление окна использует desktop ID и StartupWMClass; короткий кеш сохраняет точку закрывшегося приложения до обновления строки. WindowTracker также передаёт setMinimizedGeometry стандартному KDE-протоколу, чтобы штатная анимация имела правильную точку назначения без нашего эффекта.

Анимация Genie находится в `kwin/geniegeometry.h` и не меняет материал или компоновку Dock. Сначала quintic smoothstep формирует криволинейную горловину к иконке (0–46% перехода), затем полотно протягивается через неё (30–100%). Краткое диагональное натяжение в начале зависит от стороны расположения иконки. Восстановление проходит ту же геометрию в обратную сторону. Текстура остаётся почти непрозрачной до последних 7.5% раскрытия; умеренный 9-tap blur действует только во время движения. Общая длительность около 620–650 мс при скорости 1, с непрерывным разворотом незавершённого перехода.

Сетка адаптивная: 12–32 столбца и 32–64 строки, без округления вершин до физических пикселей. Чистая математическая функция проверяется отдельно: точные начальные/конечные координаты, форма горловины, конечность чисел и отсутствие перевёрнутых ячеек на 201 временном срезе и четырёх положениях иконки. KWin перенаправляет настоящую текстуру окна, а не рисует её статичную имитацию. У окна без сопоставленной иконки остаётся простой безопасный переход. Полноэкранные, системные, lock-screen и popup-окна исключаются.

Размытие временное, без постоянного repaint в покое. Динамический overlap вычисляется по frameGeometry видимых normal/dialog окон текущего рабочего стола и activity. Исходная геометрия Dock сохраняется во время скрытия, что исключает самопроизвольный цикл hide/reveal.

Завершение перехода отдельно от его отмены. После последнего кадра закрытия/сворачивания освобождается forced-visible ref, затем offscreen redirect. Окно отмечается как settled-hidden без удержания текстуры или deleted ref. Если другой эффект ещё удерживает его видимым, повторная отрисовка исходного окна подавляется до удаления/восстановления. Проверка активности учитывает такой guard только пока scene item действительно видим; таймерного repaint нет. Повторный запуск/восстановление снимает guard. Repaint во время движения и при очистке охватывает объединение expandedGeometry и иконки, а не только исходное положение окна, чтобы не оставлять куски деформации за его границами.

QA-сборка умеет намеренно удерживать собственный probe на 1600 мс после начала скрытия (`MACGLASS_TEST_TAIL_HOLD=1`). Это воспроизводит наличие чужого visible/deleted ref после конца анимации. В production такого удержания и capture API нет. Счётчик `tailSuppressed` показывает предотвращённые поздние попытки отрисовки, а не количество пользовательских ошибок.

В `desktop-v6` отдельно устранено наложение Squash на Genie в начале сворачивания. Squash не проверяет minimized grab role и успевает изменить WindowPaintData в paintWindow до нашего drawWindow; при ускорении KDE до 0.25 его fade заканчивается гораздо раньше Genie. Для собственных Minimize/Restore в apply нормализуются inherited opacity/scale/translation/rotation перед нашей деформацией. Opacity WindowItem уже находится в offscreen-текстуре, поэтому нейтральный множитель равен 1. Brightness/saturation и системные настройки эффектов не меняются. Счётчики minimizeConflicts/minimizeStartFrames/minimizeStartFades проверяют, что конкурирующий fade реально встретился, но не прошёл в первые кадры Genie. Это дополнение к защите конца, а не замена ей.

## Выбор окна при наведении

Через 2000 мс DockItem запрашивает WindowSwitcher; движение указателя перезапускает ожидание. Используется центр-относительная координата всего Dock, а не локальные координаты прыгающего delegate: пружина и дробное округление layer-shell не должны бесконечно сбрасывать таймер. Смещение до 1 DIP накапливается, но само по себе не считается новым движением. Окна берутся из реального списка WindowTracker с внутренним token и UUID. Карточка активирует ровно свой token. При переходе мыши на панель есть 550 мс на пересечение промежутка; пока указатель над панелью или исходной иконкой, она открыта. Hover-панель не запрашивает клавиатурный фокус.

Если registry действительно объявил `zkde_screencast_unstable_v1`, отдельный необязательный QML Loader использует TaskManager.ScreencastingRequest по UUID и PipeWireSourceItem. Потоки существуют только пока видны карточки; запрос разрешён и для свёрнутых окон, но кадры для них зависят от композитора/приложения. PipeWireSourceItem остаётся visible до первого кадра: обратная привязка visible=ready приостанавливала поток и никогда не давала ему стать ready. При отсутствии протокола, модуля или кадра показывается текст состояния, не повторная иконка и не выдуманный снимок. Это не даёт ShaderEffect доступ к произвольному рабочему столу.

WindowSwitcher снова использует glassMaterial=true: одна линза, tint не ниже .28, finish=.4, opticScale=.3, blurRadius=2.5, refractionStrength≤6, refractionWidth=10. Индивидуальные backdrop* properties публикуются в JSON линзы; отрицательное значение наследует глобальные options. Поэтому оптика Dock не меняется. Убраны общий заголовок и внутренняя рамка; сохранены прежние 194×102 DIP live-video и единственная подпись конкретного окна. Пока открыт предпросмотр, tooltip исходной иконки подавляется.

LauncherWindow имеет минимальную плотность tint .58. Обратимая revealProgress-анимация задаёт раскрытие Genie, не изменяя геометрию app-window Genie. В desktop-v8-moving-glass KWin перенаправляет собственную launcher surface в offscreen-текстуру и применяет ту же функцию MacGlassGenie::map к её сетке и ко всем стеклянным линзам. Шейдер линзы различает исходную координату для rounded SDF/кромки и деформированную координату для выборки настоящего фона. Так фон остаётся живым и искажённым во время полёта, без скачка между двумя независимо анимируемыми слоями.

В desktop-v9-live-underlay устранена оставшаяся зависимость zoom от исходного local: вся выборка движущегося фона, включая масштаб, использует samplePosition и текущий деформированный lensCenter. Это существенно при пользовательском CenterZoom=.94; при 1 ошибка скрывалась нулевой добавкой. Сам материал и неподвижный shader path Dock сохранены. Регрессионный GPU-тест проверяет независимость выборки от source UV и реакцию на обновление backdrop.

В desktop-v10-panel-lifecycle progress публикуется независимо от внешнего bounding rect и вызывает scene damage всей траектории. postPaintScreen поддерживает repaint только в течение перехода: статичный фон больше не зависит от побочных перерисовок QA-сетки. Конец hide двухэтапный: terminalHidden делает client content прозрачным, задания после sync/swap возвращают GUI callback с generation token, и лишь затем окно снимается. При неэкспонированном output действует safety timeout 750 мс. Отдельный KWin guard подавляет старое полотно после снятия redirect и до удаления/нового предъявления панели. Тест ordinaryClientPanelLifecycle запускает обычный клиент без QtTest/capture флагов, на неподвижном фоне и с повторными открытиями; QA удерживает закрытую surface 600 мс и сравнивает кадры собственной сцены с baseline. Production не содержит этого capture API.

Описание frame/icon/openness передаётся вместе с линзами и проверяется до применения. Копия фона и BackgroundEffectItem следуют фактическим границам воронки. Сетки имеют адаптивную плотность; новые offscreen-ресурсы освобождаются при завершении/выгрузке. Scissor ограничивает рисунок destination damage; GL-состояние восстанавливается. Нативный canvas занимает выбранный экран для пути к иконке, но input region — деформированный rounded contour, а не его большой bounding rectangle. Внешний клик также проверяется по контуру во время движения. По окончании скрытия окно снимается. Переход конечный; idle не перерисовывается ради анимации.

Наличие native panel Genie согласуется отдельной capability. Путь выбирается на старте перехода, чтобы поздний ответ DBus не менял способ отрисовки посреди полёта. Без native-возможности используется настоящий Qt Quick ShaderEffect/GridMesh 32×64 с предварительно собранными panel-genie.vert/frag.qsb; у клиента нет текстуры рабочего стола, поэтому такой fallback не обещает настоящее backdrop refraction в движении. Software fallback — scale/fade. Reduced Motion завершает переход немедленно.

В поиске один явный caret шириной 2 DIP; он мигает раз в 500 мс и становится видимым после ввода/перемещения. Таймер выключен при закрытии панели/потере фокуса. Результаты используют конечное появление opacity/scale/translate с ограниченным stagger ≤126 мс; index=-1 при удалении delegate зажат, отрицательных PauseAnimation нет. Эти изменения относятся к каталогу, а не к добавлению/удалению приложений в Dock.

В desktop-v7-panels добавлен InputEventSpy: нажатие/касание вне опубликованного rounded input rect собственной панели посылает только её имя по DBus. Событие не фильтруется, координаты и содержимое чужих окон клиенту не сообщаются. Блокировка экрана отключает эту реакцию. Без модуля сохраняется прежний focus-loss/Escape fallback. В desktop-v8-moving-glass к apply() добавлена только отдельная ветка собственного launcher перед прежней логикой app-window Genie desktop-v6; математика Minimize/Restore и исправления начала/конца не переделывались.

KDE-протокол специфичен для композитора; политика и ABI/API могут меняться. Неизвестный app ID не всегда сопоставляется с установленным desktop file. Переподключение после полного рестарта compositor connection отдельно не сертифицировано. Подробности — KWIN_STAGE4_RESEARCH.md.

## Настройки и анимации

DockSettings валидирует числа/строки, читает XDG INI, предоставляет live properties. Изменения уведомляют QML сразу; запись объединяется таймером 250 мс. Завершение приложения сбрасывает ожидающую запись. До первого изменения файла нет. Параметры-пустышки рефракции не добавляются.

Gaussian falloff вычисляется в базовой системе всего ряда, включая крайние управляющие кнопки. Ни одна крайняя ячейка больше не имеет фиксированного масштаба. Координата фиксируется по pointer event относительно центра Dock; изменение ширины без нового события не пересчитывает старую координату и не создаёт feedback loop. SpringAnimation управляет фактической шириной каждой ячейки, layout исключает перекрытие. Уменьшение движения отключает magnification/пружины, ограничивает появление панелей и автоскрытие. Подпрыгивание привязано к pending job, имеет конечное число циклов и прекращается по его завершению.

FrameDiagnostics подписывается на frameSwapped собственных окон. В режиме диагностики он раз в 5 секунд печатает статистику активных интервалов и DPR; таймер не вызывает рендер. Это не GPU profiling и не измерение latency ввода.

## Тесты

Сохранены четыре проверки предыдущего этапа. Stage4Tests проверяет каталог, поиск с вводом текста, закрепления, реальные свойства панели, пресеты, темы, blur/GPU fallback, иконки, Reduced Motion и автоскрытие. В native Wayland он создаёт собственный dock-window-probe, наблюдает его, минимизирует, восстанавливает и закрывает; пользовательские окна не являются целями теста.

Desktop launch probe, INI, кеш KSycoca, настройки и маркеры изолированы в build. UI-тест восстанавливает исходный тестовый INI. Clipped GridView delegates могут иметь ShaderEffect.Uncompiled до первого рисунка — это штатно. Ошибки шейдеров проверяются везде. При повторном использовании общего shader-info cache Qt может оставить per-instance Uncompiled даже у рисуемого материала: тесты проверяют ресурс/URL, полупрозрачный framebuffer и отличие GPU-вывода от software fallback. Тестовый код не входит в Release с BUILD_TESTING=OFF.
