# Пользовательский KWin Effect преломления

Модуль `kwin/macglassrefraction` — экспериментальный OpenGL Effect для KDE Plasma 6/KWin 6.8.0. Он обрабатывает только surface, принадлежащие процессу `org.macglass.Dock`, и получает список скруглённых поверхностей и линз через session D-Bus.

Effect не делает захват экрана из клиента. KWin использует доступный композитору render target под собственным окном, применяет слабое размытие, edge displacement, chromatic edge и отдельный проход icon lenses. При выгрузке native blur восстанавливается watchdog-механизмом.

Файлы находятся в `$HOME/.local/share/mac-glass-dock/refraction`. Модуль не записывается в `kwinrc`. При явно включённом автозапуске Dock пользовательский login-helper вызывает session.sh, который загружает установленный модуль перед клиентом. Без этого загрузка ограничена текущим сеансом.

Управление из корня проекта:

```bash
./scripts/refraction.sh build
./scripts/refraction.sh install
./scripts/refraction.sh enable
./scripts/refraction.sh status
./scripts/refraction.sh disable
```

`install` сохраняет production-модуль в `releases/<hash>` и обновляет ссылку `current`. QA-сборки отвергаются. `enable` запускает только собственный загрузчик через его точный Script ID, без общего `Scripting.start()`. Новая версия загружается по новому абсолютному пути: Qt сохраняет ранее использованные фабрики плагинов в памяти даже после выгрузки эффекта.

QML wrapper хранится по постоянному пути `refraction/native` и не перезаписывается при обновлениях. `register.qml` регистрирует его URI один раз, а `reload.qml` использует уже зарегистрированный `MacGlassBootstrap 1.0`: повторная регистрация защищённого QML-модуля из другого каталога вызывает ошибку Qt. Это отдельно проверено холодной и повторной загрузкой в изолированном сеансе.

`BackgroundEffectItem` объявляет KWin зависимость линз от фона. Буферы создаются в физическом разрешении viewport отдельно для каждого RenderView. Скроллируемые делегаты обрезаются по видимой области. В покое эффект не просит дополнительные кадры.

При включённых `WindowIntegration` и `WindowAnimations` нормальные окна с сопоставленной иконкой получают двухфазную Genie-деформацию: формирование кривой горловины, затем втягивание полотна окна. Обратный переход разворачивает ту же сетку. Без сопоставления остаётся scale/fade fallback. Полная идентичность тайминга macOS по неподвижным референсам не заявляется. Постоянный выбор эффектов Plasma не меняется. Отключение интеграции, Reduced Motion или выгрузка модуля освобождают активные анимации. Шейдер преобразует цвет по стандартному пути KWin OffscreenEffect.

Revision `desktop-v5` содержит защиту окончания: уже свёрнутое/закрытое окно не возвращается в исходную геометрию, даже если другой эффект ещё удерживает visible/deleted ref. Guard не хранит текстуру или собственную ссылку на закрытое окно и снимается при восстановлении/удалении. `tailSuppressed` в диагностике считает предотвращённые поздние отрисовки. Область repaint включает траекторию к иконке. Перед установкой/включением `refraction.sh` проверяет ненулевой модуль и `ldd -r`; линковка использует `--no-undefined`.

Revision `desktop-v6` дополнительно изолирует WindowPaintData наших Minimize/Restore от одновременно работающего Squash. Его scale/translation/opacity больше не накладываются на Genie: исчезает быстрый полёт к старой панели и возврат перед нашей анимацией. Системный Squash остаётся включён. Диагностика `minimizeConflicts` считает встреченные ранние чужие fade, `minimizeStartFades` — пропущенные в первые кадры (ожидается 0). Проверено с KDE AnimationDurationFactor=0.25 в частном тестовом XDG, без изменения пользовательской скорости KDE.

Revision `desktop-v7-panels` сохраняет эту математику без изменений. Добавлены локальные overrides blurRadius/refractionStrength/refractionWidth для линз панелей: предпросмотр использует 2.5/≤6/10, а Dock наследует свои прежние options. Для travel-canvas каталога фон копируется только в объединении линз с защитным отступом. Наблюдатель [InputEventSpy KWin 6.8](https://raw.githubusercontent.com/KDE/kwin/v6.8.0/src/input_event_spy.h) отправляет имя собственной панели при внешнем нажатии/касании, ничего не фильтруя и не записывая чужой ввод. Захват/синтетические testPanelPress/testPointer по-прежнему компилируются исключительно в отдельную QA-сборку.

Revision `desktop-v8-moving-glass` добавляет compositor-side Genie каталога. Отдельный panelgenie.cpp перенаправляет только launcher surface, строит сетку 48×96 и освобождает redirect после перехода. Линзы деформируются той же функцией: исходные UV определяют скругления и кромку, деформированная позиция — реальные фоновые пиксели. Поэтому blur/refraction не отключаются в движении и не превращаются в статичный прямоугольник. Capability panelGenieSupported и счётчики panelMotionFrames/warpedLenses позволяют проверить действительный путь. Материал самого Dock и глобальные числовые настройки не изменены. CPU-контур input region совпадает с деформацией, включая проверку внешнего клика в узкой части воронки.

Первый map каталога не показывает исходный большой прямоугольник: клиент ждёт panelMotionReady с идентификатором своей текущей Wayland surface, после установки redirect запускает revealProgress. При отсутствии подтверждения за 700 мс выбирается клиентский mesh-fallback; поздний ответ не переключает режим посреди перехода. Это отдельная защита от стартовой вспышки, без изменений проверенной анимации сворачивания обычных приложений.

Revision `desktop-v9-live-underlay` исправляет оставшуюся source-space добавку zoom при движении каталога. При CenterZoom≠1 (у пользователя .94) исходные UV увлекали часть деталей фона за полотном. Теперь zoom считается от деформированного центра линзы в экранных координатах, а source UV определяют только rounded SDF и кромку. Неанимированная ветка, в том числе стекло Dock, не менялась. GPU-регрессия меняет source UV при фиксированной destination geometry и требует неизменного фона; отдельная смена фоновой текстуры должна сразу менять результат. Подробнее: [живой фон каталога](AGENT_LIVE_UNDERLAY_REPORT.md).

Revision `desktop-v10-panel-lifecycle` дополняет это исправлением жизненного цикла. Каждый шаг revealProgress публикуется даже при постоянном bounding rect; в течение конечной Genie-анимации явно перерисовывается сцена по траектории, а не только клиентский buffer. В конце Qt отправляет прозрачный кадр до hide. Собственный compositor guard не даёт удерживаемой другим эффектом закрытой панели отрисовать исходный прямоугольник. В отличие от app-window guard, это отдельный набор только собственных launcher surface без retained texture/ref; он снимается при повторном предъявлении/удалении. Счётчики panelBackgroundRepaints/panelTailSuppressed не читают чужой ввод или изображения. QA-сборка отдельно проверяет обычный клиент на неподвижном фоне с намеренным удержанием закрытой поверхности. [Отчёт](AGENT_PANEL_LIFECYCLE_REPORT.md).

```bash
qdbus6 org.kde.KWin /MacGlassRefraction org.macglass.Refraction.status
qdbus6 org.kde.KWin /MacGlassRefraction org.macglass.Refraction.diagnostics
```

Отключение текущего сеанса:

```bash
qdbus6 org.kde.KWin /Effects org.kde.kwin.Effects.unloadEffect macglassrefraction
qdbus6 org.kde.KWin /Scripting org.kde.kwin.Scripting.unloadScript macglass-optics-user-loader
```

Это compositor-assisted оптика, а не полная физическая модель Liquid Glass. HDR, разные DPR на нескольких мониторах, произвольные трансформации окон и сторонние эффекты KWin требуют отдельной проверки. QA-сборка с захватом существует только для вложенного тестового KWin и не устанавливается.
