# Отчёт — этап 3

Дата проверки: 20 октября 2026 года. Работа выполнена в существующем проекте `mac-glass-dock`.

## Результат

Реализован самостоятельный нижний Dock для текущего KDE Plasma / Wayland: размещение через layer-shell, системные иконки, запуск desktop entries, непрерывное увеличение с пружинной анимацией, GPU-материал стекла и системный blur при доступности композитора. Рабочая модульная загрузка QML сохранена.

Это собственный стеклянный материал, а не полная копия macOS Liquid Glass. Преломления изображения рабочего стола пока нет.

## Архитектура и поведение

C++ отвечает за настройки, приложения и интеграцию с композитором. QML получает их через обязательные типизированные свойства; глобальные context properties больше не нужны. `loadFromModule("MacGlassDock", "Main")` сохранён. Сгенерированный `qmldir` указывает `prefer :/qt/qml/MacGlassDock/`, тип `Main` соответствует `qml/Main.qml`.

LayerShellQt задаёт нижний anchor и горизонтальное центрирование, слой Top, margin 10, exclusive zone 0 и отсутствие клавиатурного фокуса. Это позволяет существующей панели продолжать работать. Резервирование пространства/изменение strut для собственного Dock не применяется. Для preview используется обычное окно с заголовком и кнопкой закрытия.

Размер контейнера складывается из фактической ширины ряда и небольших полей; высоты достаточно для максимального zoom и подсказки. Область ввода — объединение скруглённой поверхности и геометрии иконок. Прозрачные углы и верхний запас не включены в input region. Для Wayland все координаты задаются в логических пикселях, без ошибочного повторного умножения на DPR. Размеры текстур иконок учитывают DPR.

При наведении координата указателя переводится в базовую систему ряда. Масштаб определяется Gaussian-функцией расстояния и сглаживается `SpringAnimation`. Каждая ячейка занимает текущую анимированную ширину; соседние иконки не накладываются друг на друга. Ширина окна изменяется вместе с рядом. Проверен проход указателя через несколько элементов и плавный возврат.

Закрепления разрешаются через `KService`, запуск выполняется `KIO::ApplicationLauncherJob` с асинхронной обработкой ошибок. Shell-команды из пользовательских строк не собираются. Конфигурация принимает desktop ID, а абсолютные пути к приложениям отклоняются. Неустановленные приложения приглушаются и показывают ошибку. Точка под иконкой означает ожидающий запрос запуска, не наличие открытого окна.

Настройки читаются из `$XDG_CONFIG_HOME/mac-glass-dock/settings.ini`, по умолчанию `~/.config/mac-glass-dock/settings.ini`. Автоматической записи нет. Пример и диапазоны документированы в README. Изменение файла применяется после перезапуска; `auto` реагирует на системную светлую/тёмную тему. Анализа пикселей обоев нет.

## Реализованные эффекты

- Системный blur через `KWindowEffects::enableBlurBehind`, ограниченный скруглённой областью стекла.
- Проверка `isEffectAvailable`; запрос contrast только при сообщённой поддержке. В этом сеансе поддержка background contrast не подтверждена, поэтому она не заявляется как работающая.
- Процедурный SDF-материал: нейтральный полупрозрачный градиент, мягкая тень, сглаженные скругления, внутренняя подсветка, тонкий светлый край.
- Локальный блик и изменение подсветки при движении указателя; статичная микронеоднородность материала.
- Пружинный zoom с влиянием на соседей, анимация нажатия, мягкий hover и всплывающие названия.
- Более плотный материал без системного blur; QML fallback при software renderer, выключенном GPU или ошибке ShaderEffect.

Шейдер предварительно компилируется `qt_add_shaders` в `:/effects/glass.frag.qsb`. `qsb -d` подтвердил fragment stage и шесть вариантов: SPIR-V, GLSL ES 100, GLSL 120/150, HLSL 50, MSL 12. ShaderEffect действительно достиг состояния Compiled на проверенном GPU backend.

## Сборка и тесты

Подэтапы A, B, C, D и E последовательно собирались; существующий QML smoke-тест оставался рабочим. По мере разработки добавлены расширенные проверки, найденные ими ошибки исправлены.

Итоговая проверка:

| Проверка | Результат |
| --- | --- |
| `./scripts/build.sh` | Успешная Debug-сборка |
| Release, `BUILD_TESTING=OFF` | Успешно; зависимость от Qt Test отсутствует |
| Release `--smoke-test` с offscreen | Код 0 |
| `ctest --test-dir build --output-on-failure` | 4/4 passed, код 0 |
| `mac-glass-dock_qmllint` | Без предупреждений и ошибок |
| Wayland Dock `--interaction-test` | 7 passed, 0 failed, код 0 |
| Wayland preview `--interaction-test` | 7 passed, 0 failed, код 0 |
| Preview, `QT_SCALE_FACTOR=1.5` | 7 passed, 0 failed, код 0 |
| Обычный запуск с пятью реальными закреплениями и `--capture` | Успешный кадр, код 0 |

CTest включает `settings_validation_test`, `qml_smoke_test`, `dock_interaction_test`, `qml_failure_is_rejected`. Отрицательный тест использует отсутствующий модуль и проверяет ненулевой exit status. Проверки взаимодействия охватывают загрузку всех иконок, наличие QSB, hover/возврат, изменение ширины, отсутствие перекрытий, рендер, input mask на Wayland, клик, асинхронное завершение KIO job, отсутствие приложения и закрытие окна.

Клик выполнялся по безопасному desktop entry, запускающему реальный тестовый executable. Он пишет маркер в `build/test-launch.marker`; пользовательские приложения в ходе автоматизированного теста не открываются. Исходные закрепления отдельно проверены обычным запуском и кадром.

Выявленная при разработке ошибка headless: QPA offscreen не предоставлял пути XDG к темам иконок. Она исправлена явным добавлением существующих каталогов `icons` из `QStandardPaths::GenericDataLocation`. Используется уникальный image-provider `dockicons`, результат — `QImage`. Все пять иконок теперь проходят проверку Image.Ready и в headless, и в Wayland.

В итоговых выборках покоя за 250 мс в Dock, preview и 150% зарегистрировано 0 новых кадров. Это локальная проверка отсутствия непрерывной перерисовки, не сертификация 60 FPS на любых GPU. Долговременный профиль CPU/GPU, memory leak audit и frame timing под нагрузкой не выполнялись.

## Границы визуальной проверки

Графическая сессия теперь доступна. Обычный Dock и preview действительно запускались на Wayland; проверены реальные framebuffer-кадры Qt Quick в покое и при увеличении, включая 150%. Кадры просмотрены агентом. Ошибок ShaderEffect и загрузки QML в финальных проверках не обнаружено.

Отдельно зафиксирован реальный трафик композитора: создание `zwlr_layer_surface_v1`, нижний anchor, margin 10, exclusive zone 0, отключённый keyboard focus, `wl_surface.set_input_region`, capability blur и `ext_background_effect_surface_v1.set_blur_region`.

Полный снимок рабочего стола не снимался. `grabWindow()` содержит только собственный framebuffer, поэтому финальная композиция blur поверх реальных обоев, визуальное сосуществование со всеми вариантами панелей и длительное субъективное ощущение движения требуют пользовательской проверки. Успешная сборка сама по себе не использовалась как доказательство визуальной корректности.

Логи и снимки находятся в игнорируемом `build/`: `stage3-build.log`, `stage3-ctest.log`, `stage3-native.log`, `stage3-preview.log`, `stage3-150.log`, `qmllint.log`, `wayland.trace.log`, `release-build.log`, `stage3-default.png`, `stage3-dock.png`, `stage3-dock-hover.png`, `stage3-preview.png`, `stage3-150.png` и варианты `-hover`.

## Ограничения и известные вопросы

- Нет наблюдения за всеми открытыми окнами, переключения/минимизации существующего окна и индикатора «приложение работает». Для этого нужен отдельный адаптер KWin/Wayland и сопоставление desktop ID.
- Нет настоящего преломления фонового изображения и отражений реальной сцены.
- Автотема следует системной теме, не определяет яркость участка обоев.
- Нет UI настройки/редактирования закреплений, hot reload, автоскрытия и drag-and-drop.
- Нет полноценной навигации с клавиатуры в нефокусируемой layer-shell поверхности. Закрытие Dock сейчас выполняется через терминал; preview имеет стандартную кнопку закрытия.
- Выбор монитора, hotplug, переключение между несколькими экранами, перезапуск KWin и изменение capabilities в покое требуют следующего этапа. На неподдерживающем layer-shell Wayland-композиторе следует использовать preview; основной путь проверен именно на текущем KWin.
- X11 имеет только базовый fallback позиционирования; он не тестировался как основной режим.
- При большом списке закреплений размер уменьшается для экрана, но отдельный overflow/scroll UX пока отсутствует.
- В offscreen не существует native input mask и системного blur; их проверка выполнялась в отдельном реальном Wayland-запуске.
- В финальной проверенной конфигурации критических ошибок не обнаружено. Поддержка иных GPU/композиторов и полного набора конфигураций Plasma не заявляется без тестов.

## Запуск

```bash
cd /home/nikita/Projects/mac-glass-dock
./scripts/build.sh
ctest --test-dir build --output-on-failure
./build/mac-glass-dock
```

Preview: `./build/mac-glass-dock --preview`. В терминале процесс Dock останавливается Ctrl+C. Полный список параметров: `./build/mac-glass-dock --help`.

Повторить native-тест с безопасным тестовым приложением:

```bash
XDG_CONFIG_HOME="$PWD/build/test-config" \
XDG_DATA_HOME="$PWD/build/test-data" \
XDG_CACHE_HOME="$PWD/build/test-cache" \
./build/mac-glass-dock --interaction-test --capture "$PWD/build/dock.png"
```

Для preview добавьте `--preview`, для дополнительного масштаба — `QT_SCALE_FACTOR=1.5` в окружение. Для кадра обычных закреплений: `./build/mac-glass-dock --capture "$PWD/build/default.png"` (тестовая сборка, сохраняет кадр и завершает процесс).

## Что ещё необходимо для полного Liquid Glass

1. Разрешённый источник реального изображения за конкретной поверхностью на стороне KWin: обычный клиент Wayland не может произвольно читать рабочий стол.
2. Согласованный протокол координат, масштаба, цвета/HDR, синхронизации и владения текстурами. Фоновый источник должен быть независим от текущего процедурного материала.
3. Карта нормалей/толщины, выборка со смещением, оптическая рефракция краёв, отражения окружения и контроль читаемости. Процедурный блик сам по себе эти механизмы не заменяет.
4. Исследование доступности compositor-side эффекта, его политики доступа и совместимости с разными KWin. Скриншоты обоев и обход ограничений Wayland не подходят.
5. GPU-профили качества, корректная линейная композиция, измерение frame timings на 60/120/144 Гц, длительные тесты памяти, HiDPI и нескольких мониторов.

Следующему агенту стоит начать с модели открытых окон и тестов multi-monitor/hotplug, затем отдельно проектировать разрешённую интеграцию рефракции с KWin. Исходные материалы и ресурсы Apple не используются.
