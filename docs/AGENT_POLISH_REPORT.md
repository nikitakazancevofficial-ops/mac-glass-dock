## Почему окно мигало в начале

Это отличалось от ранее исправленной вспышки в конце. Установленный штатный Squash параллельно менял размер, положение и прозрачность окна. Он не проверяет minimized grab role, поэтому grab сам по себе его не останавливает. Системная скорость KDE равна 0.25: короткий Squash успевал отвести/пригасить окно и закончиться, пока наша более длинная Genie ещё продолжалась. Пользователь увидел именно два полёта в замедленной записи.

В `apply()` только для наших Minimize/Restore теперь нормализуются inherited scale/translation/rotation и множитель opacity перед собственной деформацией. WindowItem opacity уже включена в перенаправленную текстуру, поэтому множитель равен 1, без повторного умножения на прозрачность окна. Brightness/saturation не сбрасываются. Squash не выгружался, настройки эффектов KDE не переписывались. Защита завершения desktop-v5 сохранена.

Baseline с прежним поведением и AnimationDurationFactor=0.25 воспроизвёл 2 ранних чужих fade (`build/min-start-fast-baseline.log`). Исправленный прогон реально встречает конфликт, но не пропускает его в выходную opacity первых кадров. На рабочем столе перед обновлением клиента зафиксированы 74 встреченных конфликта и **0 начальных fade на 222 проверенных ранних кадрах**. Пользователь также подтвердил исчезновение мигания. Это не обещание отсутствия любых багов во всех программах.

## Предпросмотр окон

- Ожидание **5000 мс**, движение указателя перезапускает таймер. Простое название приложения может показываться раньше; список окон — отдельно.
- Реальный KDE ScreencastingRequest по UUID + PipeWireSourceItem. Причина прежней иконки: `visible: ready` блокировало старт, поскольку невидимый PipeWireSourceItem приостанавливает собственный поток. Теперь он остаётся видимым до получения кадра.
- Ресурсы потока создаются только для видимых карточек и освобождаются с закрытием панели. Изображение не заменяется повторной иконкой. При невозможности получения показывается честное текстовое состояние.
- Для свёрнутого окна также запрашивается поток; возможность/свежесть его кадров зависит от KWin и клиента. Окно ради предпросмотра принудительно не разворачивается.
- По последней просьбе пользователя убраны стеклянные слои именно из WindowSwitcher. Панель и карточки — обычные скруглённые нейтральные поверхности. Ввод/выбор конкретного token сохранён, фокус клавиатуры не захватывается.
- Окно предпросмотра исключено из compositor-линз и blur behind. Стекло Dock и других панелей не переделывалось.

Native тест получил ненулевой PipeWire node, дождался ready и сравнил область видео в двух кадрах. Собственное тестовое окно меняет цвет заголовка, и это изменение действительно появилось в предпросмотре. Проверка выполнена на настоящих потоках вложенного KWin, не на макете или статичной иконке. Просмотрен framebuffer `build/optics-nested-real-window-preview.png`: скруглённая панель с содержимым тестового окна. Пользовательские окна/рабочий стол не захватывались для отчёта.

## Мягкое размытие

В основном разделе материала добавлен доступный ползунок **«Мягкое размытие стекла, px»**, 0–12, шаг 0.05. Он использует существующий BlurRadius kernel после выборки искажённого фона. Логотипы/текст не размываются, нового FBO-прохода нет. Дублирующий ползунок удалён из расширенного раздела.

По последнему требованию сохранить понравившееся стекло текущие значения не менялись, включая BlurRadius=0.77. Это изменение доступности настройки, а не новый физический blur-алгоритм. Native UI-тест действительно сдвигает ползунок и проверяет изменение радиуса в опубликованных compositor options; отдельный shader-тест проверяет различие пикселей при разных радиусах.
