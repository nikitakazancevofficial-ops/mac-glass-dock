# KWin: границы интеграции этапа 4

Проверенная система: KWin/LayerShellQt/KWayland 6.8.0, KF6 6.31, Qt 6.12, Wayland. Эта заметка не является инструкцией автоматически изменять рабочий стол.

## Окна приложений

Необязательный `WindowTracker` использует клиентскую KWayland и объявленный композитором `org_kde_plasma_window_management`. Подключение выполняется через `ConnectionThread::fromApplication` и собственный `Registry` поверх соединения Qt. Включение по умолчанию отключено. Пользователь включает его в панели настроек либо параметром `--enable-window-tracking` для одного запуска.

Окна группируются по desktop ID; учитывается StartupWMClass из KService. Индикаторы получают реальные `isActive`, `isMinimized`, skip-taskbar и количество окон. Запросы activate/minimize/close проверяют наличие токена окна и соответствующую capability. Токен локальный, не является PID или произвольной командой. При отсутствии протокола модель не выдумывает работающие приложения.

Это KDE-специфический Wayland-протокол, не универсальный стандарт. KWayland связывается только если найдена соответствующая CMake-цель. Новая версия KWin может изменить доступность/политику протокола или семантику app ID. Неизвестные app ID могут не совпасть с desktop entry; для них возможен общий значок. Автоматический рестарт KWin и переподключение после полного обрыва соединения требуют отдельных тестов.

## Настоящая рефракция

`ext_background_effect_manager_v1` сообщает capability blur, а `set_blur_region` передаёт область размытия. Текстуру изображения за окном этот протокол клиенту не отдаёт. QML ShaderEffect также не получает пиксели чужих окон.

У текущего KWin установлены заголовки C++ Effect API (`Effect`, `OffscreenEffect`, `EffectWindow`), то есть compositor-side исследование возможно. Однако OffscreenEffect сам по себе перенаправляет рисунок конкретного окна, а не автоматически предоставляет безопасный фон под ним.

Обоснованная будущая архитектура: отдельный opt-in эффект KWin рисует в точке стека до стеклянной поверхности, получает разрешённый underlay, рассчитывает нормали/толщину и выборку смещённого фона в пространстве вывода, затем композитит поверхность. Потребуются damage tracking, HDR/linear-light, дробный масштаб, исключение рекурсивного включения самого Dock, корректный жизненный цикл текстур и явное согласование поверхности по app ID/namespace. Установка такого эффекта — отдельная операция пользователя. C++ ABI KWin следует считать привязанным к версии.

Готовый модуль рефракции в этом этапе не устанавливается и не загружается. Не добавлен фиктивный plugin, который только окрашивает окна и называется рефракцией. Текущий GLSL материал рассчитывает объёмную кромку, Fresnel-like свет и художественные отражения, но не заявляет преломление рабочего стола. Захват экрана, подмена обоев и обход разрешений Wayland не применяются.

## Magic Lamp / Genie

Read-only запросы KWin Effects показали: `magiclamp` поддерживается, но не загружен; `blur` загружен. Ничего не переключалось. Системное сворачивание в Dock запрашивается через PlasmaWindow, а анимацию выбирает сам KWin. При желании пользователь может самостоятельно выбрать Magic Lamp в «Параметры системы → Поведение рабочей среды → Эффекты рабочего стола». Совместимость с другими эффектами и визуальный результат затем нужно проверить вручную. Это не обязательное действие для работы Dock.

## Скругления сторонних окон

Собственные панели проекта имеют скругления shader/input/blur. Из обычного Dock нельзя универсально скруглить стороннее Wayland-окно, особенно с client-side decoration. Возможны отдельный декоратор или compositor effect, но это глобальные пользовательские изменения и отдельный проект совместимости. Настройки тем, декораций, приложений и KWin в этом этапе не изменяются.
